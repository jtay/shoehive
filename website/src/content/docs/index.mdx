## Your rules, as code

These are the rules of tic-tac-toe, from the
[example in the repository](https://github.com/jtay/shoehive/tree/main/examples/tic-tac-toe)
(`winnerOf` is a plain function in the same file). Input is checked against the schema,
out-of-turn moves are rejected, and a rejected action changes nothing.

<Snippet file="examples/tic-tac-toe/src/game.ts" region="game" />

Host it, and any number of tables can be played at once:

```ts
import type { AnyGame } from 'shoehive';
declare const ticTacToe: AnyGame;
// ---cut---
import { createServer } from 'shoehive/server';

await createServer({ games: [ticTacToe] }).listen({ port: 3000 });
```

## What you get

<CardGrid>
  <Card title="Typed end to end" icon="seti:typescript">
    Action inputs and views are inferred from your game, all the way to `useTable()` in React. No
    code generation.
  </Card>
  <Card title="Hidden information" icon="eye">
    Clients only ever receive what your `view()` lets each seat see. Hole cards stay hidden.
  </Card>
  <Card title="Turns and rounds" icon="list-format">
    Turn-based games, and round-based play where everyone acts at once against a timer.
  </Card>
  <Card title="Reconnects and restarts" icon="random">
    Guest sessions with resume tokens. Tables survive a server restart with SQLite, Postgres or
    Redis.
  </Card>
  <Card title="Deterministic" icon="seti:clock">
    Seeded randomness and a recorded action log power tests, replays and time travel in the
    devtools.
  </Card>
  <Card title="Test without sockets" icon="approve-check">
    `createTestTable(game)` runs your rules in a unit test with a fake clock.
  </Card>
</CardGrid>
