## 1. The game

A game is one `defineGame` call. It says who plays, what the starting state is, whose turn it
is, and what players can do. Start with the shape and one action:

```ts
import { defineGame, reject } from 'shoehive';
import { z } from 'zod';

type Mark = 'X' | 'O';

export const ticTacToe = defineGame({
  id: 'tic-tac-toe',
  name: 'Tic Tac Toe',
  seats: { min: 2, max: 2 },

  setup: () => ({
    board: Array<Mark | null>(9).fill(null),
    winner: null as Mark | 'draw' | null,
  }),

  turns: { order: 'round-robin' },

  actions: {
    place: {
      input: z.object({ cell: z.number().int().min(0).max(8) }),
      run({ state, seat, input, ctx }) {
        if (ctx.turn.seat !== seat) reject('NOT_YOUR_TURN');
        if (state.board[input.cell]) reject('CELL_TAKEN');
        state.board[input.cell] = seat === 0 ? 'X' : 'O';
        ctx.turn.next();
      },
    },
  },
});
```

- **Seats.** The table holds two seats, and the game starts when both are taken.
- **State.** `setup` returns the starting state: nine cells and a winner. State must be plain
  JSON, so there are no classes, `Map`s or `Date`s.
- **Turns.** With `turns`, the engine tracks whose turn it is in `ctx.turn`. `round-robin`
  goes through the seats in order, starting with seat 0.
- **Input.** `input` is a [zod](https://zod.dev) schema. Anything that does not match, such
  as `{ cell: 9 }`, is refused with `INVALID_INPUT` before your code runs.
- **Reject.** `run` changes `state` directly. `reject('CELL_TAKEN')` stops the action and
  throws away every change it made, and the player gets that error code. Game codes are
  `SCREAMING_SNAKE_CASE` and may not reuse a built-in code.

The engine does not decide for you that only the seat on turn may act. You check it, which is
why the first line of `run` rejects `NOT_YOUR_TURN`.

## 2. Test the rules

`shoehive/testing` runs a table in memory, with no server or sockets.
`createTestTable` seats the players, `t.act(seat, name, input)` plays as one of them, and
`t.state` and `t.meta` are what the server would hold.

<Snippet

A rejected action is a promise that rejects with the error, so `toMatchObject` can check its
`code`. `source: 'game'` tells it apart from errors Shoehive raises itself.

<Snippet
  file="packages/create-shoehive/templates/tic-tac-toe/test/game.test.ts"
  region="win"

`verifyReplay()` is worth ending every test with. It replays the table's action log from
scratch and fails if the result differs from the live state. That catches a game that reads
the clock or `Math.random()` instead of `ctx.now()` and `ctx.random`, which would break
reconnects and history. The template's file has three more tests, for input validation, a
taken cell and the game not starting with one player.

```sh
npm test
```

`createServer` takes the list of games it can host. The `secret` signs the resume tokens that
let a guest keep their seat after a reload. `npm run dev` sets a random one for the session, and
in production the server refuses to start without `SHOEHIVE_SECRET`. Never write one into the
code: whoever knows it can sign in as any guest. The `devtools` option turns on the inspector,
in development only.

The rest of `src/server.ts` is a small static file server for the built web app. The one line
that matters is this one, which adds the Shoehive WebSocket endpoint (at `/shoehive`) and the

## 5. Play it

```sh
npm run dev
```

This starts the Vite dev server and the game server together. Open http://localhost:5173 in
two windows, one of them private, so that each is a different guest. Create a game in one,
take a seat, then open the same address in the other and take the second seat. Play to a win.
Try clicking out of turn, and reload a window mid-game: you keep your seat.

## 6. Look inside

The game server printed an inspector link when it started (`Devtools inspector: ...`). Open
it while a game is running. You can see the table's state, each seat's view next to the
spectator's, and the action log, including the moves the game rejected. See
[devtools](/reference/devtools/) for what else it does.
